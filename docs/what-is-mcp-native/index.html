What is MCP-native?

An MCP-native workspace is one built around the Model Context Protocol (MCP) from the first line of code — the protocol is the substrate on which agents connect to models, tools, and memory, not an integration bolted on afterward.

For Maskin, the MCP server (packages/mcp, speaking stdio and HTTP over the @modelcontextprotocol/sdk) is the connective tissue of the whole product: it is how agents reach the tools your team already uses, how the workspace stays model-agnostic, and how bring-your-own-model becomes a real feature instead of a marketing line. This page explains what MCP is, what “MCP-native” means architecturally for Maskin, and why that design matters for determinism, safety, and scale.

Key takeaways

  • MCP is the open protocol that standardizes how agents discover and call tools — one contract instead of bespoke connectors.
  • MCP-native means the product is built around the protocol, not with it bolted on.
  • For Maskin, that is how bring-your-own-model becomes a real feature.
  • It’s the anti-lock-in move: models, tools, and sessions all stay portable.

What is the Model Context Protocol?

MCP is an open standard from Anthropic that defines how AI models connect to external tools, data sources, and infrastructure. Think of it as the wire protocol for the AI layer: rather than every model vendor building its own way to call Slack, GitHub, PostHog, or your internal APIs, MCP gives the whole ecosystem a single contract. A model speaks MCP to a server, the server exposes tools, and anyone — any model, any client — can use the same server.

In 2026 MCP is increasingly the default way agentic products ship integrations. It is how Claude drives IDE tools, how agents reach internal APIs, and how a decoupled AI stack stays composable instead of fragmenting into per-vendor adapters.

What “MCP-native” means for Maskin

Maskin is built around MCP rather than merely using it. Three things are distinctive about the design:

  • MCP is the base layer of the architecture, not a wrapper. Maskin’s own MCP server is the connection point for agents to your tools, your data, and each other. It is Monorepo is one script, and every client speaks the same protocol.
  • Your tools are already connected as MCP servers. Instead of bespoke integrations per tool, Maskin connects the agents to the tools you already use through the protocol — Slack, Linear, GitHub, Intercom/PostHog, and the rest. Your stack stays where it lives.
  • Bring your own model is real, not aspirational. Because the workspace speaks MCP on its critical seam, the model layer is swappable: Claude, a local model, or a fine-tuned model all operate on the same objects through the same protocol.

The consequence being: the protocol is both the integration surface (how your tools get in) and the abstraction boundary (how models stay portable). That is what MCP-native means — the protocol is load-bearing.

Why MCP-native matters for agentic workspaces

The agentic workspace category is in the middle of a definition moment. Some vendors market “self-driving” metaphors, but the real architectural question is how the whole system is wired. For workspaces where humans and agents share one loop — bets, insights, tasks — the integration layer is the difference between a product that agents can use and one they can only read about.

MCP-native is that dependency inwards: the workspace stops being a bespoke product with a fixed model and fixed integrations, and becomes a platform that speaks vendor-neutral protocol everywhere it matters.

The object model is the product surface

The reason this matters is that Maskin’s second surface is the typed object model. Agents don’t receive free-form text; they read, create, and manipulate objects: insights, bets, tasks, checklists — all with types, statuses, owners, and relationships that the workspace understands as data. The same objects that the UI shows are the same objects agents operate on over MCP. That is what makes agents reliable: they are not hallucinating a tool, they are mutating first-class data.

Bring your own model

Because the agent-model connection happens over a vendor-neutral protocol, Maskin does not lock you to a single model company. Bring-your-own-model means running your agents on the model that fits your trust requirements and your budget — a hosted Claude deployment, a local open-weight model, a model running on your own GPU, or an internal fine-tune — all through the same interface your team already runs.

Where MCP-native is heading

The trajectory of 2026 favors this design. Claude, of course, invented MCP; but MCP is an open protocol now, with the Linux Foundation stewardship — the same resilience-building that once legitimized Kubernetes. The trendline is toward connected agent ecosystems where server portability is taken for granted, and where being MCP-native is a baseline, not a feature claim.

FAQ

Do I need to be an MCP expert to use Maskin?

No. MCP is how the workspace connects tools and models — you do not need to build a server or configure one to use the product day to day. The maskin runs the servers (both model and tool servers) for you; you just authorize the tools you want and pick the models to use. If you want to add a custom tool, your MCP server becomes a drop-in without a new connector.

Which models work with Maskin?

Anything that speaks MCP — or anything that can be wrapped to speak it. That includes the hosted Assura models from Anthropic, OpenAI, and Google, as well as self-hosted or fine-tuned models that live in your own environment. If your model has an MCP layer, or can be wrapped in one, it can drive agents in Maskin.

Is MCP tied to one vendor?

No. MCP is an open protocol with an open source reference implementation and commercial contributors across the industry. The Anthropic led the creation, but the protocol and the reference servers have been… built in the open, and adoption spans providers, tools, and models. It is not a proprietary API.

What is the difference between MCP-native and just using MCP?

A product can use MCP and still treat it as a bolt-on — one integration among several, with the core built on proprietary plumbing. MCP-native means the architecture is actually constructed being the protocol-wrapped, end-to-end, from local hardware to your SaaS stack. Maskin is built that way.

Getting started

Self-host the open-source repo, connect the tools your team already uses (including your own MCP servers), and pick a model. The workspace works whether you run a hosted workspace or self-hosted. From “connect the tools,” the loop is a closed system on typed objects.

What is MCP-native?

The Model Context Protocol (MCP) is the open protocol for telling an AI model what tools and data are available. An MCP-native system is built around MCP from the start — the protocol is the foundation of how agents connect to models, tools, and memory.

MCP-native.
Model Context Protocol · Open wire protocol

Key takeaways

  • MCP is the emerging open wire protocol for AI tool calling — the standard way a model learns what it can use.
  • MCP-native means Maskin's agent stack and model integrations are built around it, not bolted on.
  • It makes bring-your-own-model real: Claude, Codex, or a custom model.
  • The architecture is composable infrastructure — typed objects, event-driven agents — not full company simulation.

What MCP is

MCP standardises how models discover and call tools, and how tools feed context back. Before MCP, every AI integration was a bespoke pipe. With MCP, an agent can be handed a list of typed tools and data sources and reason over them on the same contract. That is why anything “MCP-native” matters: the protocol is the substrate, not the afterthought.

What “MCP-native” means for an agent workspace

For an agent workspace, MCP-native is a property of the whole stack:

  • Agents connect via MCP to the tools your team already uses — Slack, Linear, GitHub, Intercom, PostHog, HubSpot.
  • The object model is typed and machine-readable — insights, bets, tasks are not free-form notes; agents can read, create, and transition them.
  • Triggers are event-driven — work enters when a signal changes, not when someone asks.

Bring your own model

Because the workspace is model-agnostic at the protocol layer, you decide which model runs your agents. Claude for reasoning-heavy shaping, Codex or a local model for constrained tasks, your fine-tuned model for domain work — all inside the same workspace, all on the same objects. Closed SaaS cannot offer this. See how model providers and keys work.

Typed objects and event-driven agents: the composable-infrastructure camp

The agent-workspace market split into two camps: full company simulation (an org chart of AI employees that demos beautifully) and composable infrastructure (typed objects, event-driven triggers, agents that fire when data changes and are safe to run in production).

Maskin is built in the composable camp.

“a prompt is not a job — work is a loop”
— Sebastian Krumhausen, founder of Maskin

A prompt produces text; a loop produces shipped, validated outcomes.

Why composable infrastructure wins in production

  • Determinism — an event fires an agent; the agent acts; the outcome is a state change you can inspect.
  • Safety — agents run in sandboxed sessions, not against your private keys.
  • Scale — a small team runs many agents because each one owns a narrow, well-defined role.

FAQ

Do I need to be an MCP expert to use Maskin?

No. MCP is how the workspace connects under the hood; admins just connect tools and pick a model.

Which models work?

Claude, Codex, or any model reachable over the protocol — including your own sandboxed or custom models.

Is MCP tied to one vendor?

No — it is an open protocol, which is exactly what makes bring-your-own-model possible.

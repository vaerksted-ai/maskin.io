Open source AI agents in 2026: what to run, under which license, and where the work lives

Open source AI agents are agents whose code you can run, modify and host yourself. In 2026 they fall into four lanes: frameworks you build with (LangChain, CrewAI), assistants you operate (OpenClaw, Hermes Agent, Letta), visual builders (n8n, Dify) and team workspaces (Paperclip, Maskin). Check the license first: n8n and Dify restrict commercial use.

Most roundups on this topic are one flat list that mixes SDKs, chat assistants, workflow canvases and coding tools, then ranks them by stars. That answers "what is popular", not "what should I run". This page sorts the field into lanes, checks every license against each project's own GitHub repository (on 5 October 2026), and flags the projects whose status changed this year. Coding agents have their own page: open source AI coding agents.

✓
Key takeaways
  • Pick the lane before the project. A framework, an assistant, a visual builder and a team workspace solve different jobs, and the same GitHub topic page lists all four.
  • License is the filter most lists skip. MIT and Apache 2.0 cover most of the field. n8n and Dify add commercial restrictions. Mastra and Flowise keep paid enterprise directories inside an otherwise open repo.
  • GitHub's license badge can mislead. AutoGen's repo shows CC-BY-4.0 because that covers its docs; the code is MIT. GitHub detects no standard license for Dify, n8n or Flowise because theirs are custom.
  • Check status, not just stars. AutoGen is in maintenance mode and points new users to Microsoft Agent Framework. Flowise has been archived by its maintainers.
  • Maskin is not an agent framework. It is an Apache 2.0 workspace where agents leave typed, owned records behind. It sits next to the projects below, not against them.

The four lanes

The four lanes of open source AI agents are:

  1. Frameworks: libraries you import to build your own agents
  2. Assistants: finished agents you install and operate
  3. Visual builders: canvases for wiring agent workflows
  4. Team workspaces: a shared record for people and agents

Stars below are GitHub's count on 5 October 2026. They measure attention, not fit. A 400,000-star assistant and a 14,000-star framework are not competing for the same job.

Lane 1: frameworks you build with

You write code, the framework supplies the agent loop, tool calling, handoffs and (to varying degrees) memory and tracing.

LangGraph MIT 43k From the LangChain team: "Build resilient agents"
CrewAI MIT 59k Crews (role-based agents) plus Flows (event-driven control)

AutoGen MIT (code) 61k Maintenance mode; new users are pointed to Agent Framework
Google ADK Apache 2.0 22k Code-first Python toolkit to build, evaluate and deploy agents
smolagents Apache 2.0 30k Hugging Face's "barebones library for agents that think in code"

Pydantic AI MIT 20k Python agents "typed end to end"
Mastra Apache 2.0, except ee/ directories 29k TypeScript framework for agents and AI apps

Choose by language and runtime before you compare features. Microsoft Agent Framework is the one with first-class .NET. Mastra is the TypeScript-native pick. The OpenAI Agents SDK also has a separate JavaScript and TypeScript repo, per its README. Most of the rest are Python-first.

Two status notes matter more than any feature table. AutoGen's own README says it "will not receive new features or enhancements" and tells new users to start with Microsoft Agent Framework, so a tutorial that starts with AutoGen starts from a framework its owner has stopped extending. And CrewAI's MIT code is free, but the company also sells a commercial control plane (AMP Suite) for managed deployment and governance. That is a separate product, not a license restriction, but it shapes what the open project prioritizes.

Lane 2: assistants you install and operate

These are products, not libraries. You run them, connect them to your accounts and talk to them.

Project License Stars What the repo says it is
OpenClaw MIT 391k An assistant that runs on your own computer and answers in Discord, iMessage, Slack, Teams, Telegram, WhatsApp and 20+ more channels; models and harnesses are swappable plugins
Hermes Agent MIT 251k Nous Research's "self-improving" agent: creates skills from experience and improves them in use; works with any model endpoint
Letta Apache 2.0 25k Formerly MemGPT. Stateful agents with memory that persists and improves; current code lives in the letta-code repo

An assistant that lives in your chat apps holds credentials for those apps. Read what it can reach before you install it, the same way you would before handing an intern your logins. If persistent memory is the whole point, Letta is the most purpose-built of the three. If reach (the channels, the devices) is the point, OpenClaw's repo is organized around exactly that.

Lane 3: visual builders

A canvas where you wire triggers, model calls and tools. This is the lane where license terms diverge most.

If you are leaving n8n over its license, the n8n alternative page covers the replacements by shape. The short version: Flowise's archive banner means you would inherit the maintenance, and Dify is not a license escape from n8n (next section).

Lane 4: team workspaces

Frameworks and assistants run agents. A team workspace is where several people and several agents share goals, tasks and outcomes. Swedish-speaking readers can start with AI-agenter: guide för svenska företag (in Swedish), a plain-language guide to which jobs an agent can take and who approves what.

  • Paperclip (MIT, 97k stars) is a Node.js server and React UI that orchestrates a team of agents. Its model is a company: org charts, budgets, governance and goals. You bring your own agents and choose models per agent.
  • Maskin (Apache 2.0) is organized around product work instead: signals become insights, insights become bets with a win condition, bets break into tasks, and every object has an owner. More on it below, including what it is not.

The license split that flat lists skip

The question "is it open source?" has three answers in this field, and each one bites in a different place.

Tier What you get In this field Where it bites
Permissive (MIT, Apache 2.0) Use, modify, embed, resell. Apache 2.0 adds an explicit patent grant. LangChain, LangGraph, CrewAI, OpenAI Agents SDK, Microsoft Agent Framework, AutoGen code, Google ADK, smolagents, Agno, Pydantic AI, OpenClaw, Hermes Agent, Letta, Paperclip, Maskin Almost nowhere. Keep the notice files.
Open core Open license on most of the repo, commercial license on named directories Mastra (ee/ directories), Flowise (enterprise directory), n8n (.ee. files) Using a feature from a commercial directory without a paid license
Source-available You can read, run and modify it, but not use it for everything n8n, Dify Embedding it in a product, or running it for other people

The two source-available cases are specific:

  • n8n is under the Sustainable Use License. Its docs say you may use it for your own internal business purposes or non-commercial purposes, and may distribute it only free of charge for non-commercial purposes. Anything else needs a separate agreement. Run it for your own company and it rarely matters. Embed it in a product you sell and it does.
  • Dify is "a modified version of the Apache License 2.0". Per its license text, you may not use the source to operate a multi-tenant environment without written authorization (one tenant is one workspace), and you may not remove or modify the logo and copyright information in the Dify frontend. Both limits are invisible until you build a service for customers on it.

Neither is a bad license. Both sit outside what most legal reviewers accept as open source, and n8n's own docs call the product source-available and explain why it chose not to use an open source license.

Here is what that means for the four things people actually do with the software:

You want to... MIT or Apache 2.0 Dify (modified Apache) n8n (Sustainable Use)
Run it inside your own company Yes Yes Yes, as "internal business purposes"
Use it as the backend of a product you sell Yes Yes, its license allows use as a backend service Outside the license grant, ask n8n first
Serve many customers from one install Yes Needs written authorization (one tenant is one workspace) Outside the license grant, ask n8n first
Remove vendor branding Keep the copyright notice Not in the frontend without a commercial license Keep licensing notices intact

This is a reading aid, not legal advice. Dify's license text also reserves the producer's right to adjust the agreement, so re-read the file when you upgrade. If revenue depends on the answer, ask the vendor in writing.

Three checks before you adopt anything

  1. Open the LICENSE file, not the badge. AutoGen shows CC-BY-4.0 on GitHub because that file covers documentation, and its code license is in a separate LICENSE-CODE file (MIT). Dify, n8n and Flowise have custom licenses that GitHub cannot classify. A badge that says "Other", or nothing, means read the file.
  2. Search the repo for carve-outs. Look for ee/ or enterprise directories and for the phrase "portions of this software are licensed as follows" at the top of the license. Mastra, Flowise and n8n all have it.
  3. Read the README's first screen and the last push date. AutoGen's maintenance-mode warning and Flowise's archive notice both sit at the very top of the README. A project can have 55,000 stars and no maintainers.

How to pick, in three questions

  1. Are you building an agent, or do you want one running by tonight? Building: Lane 1. Running: Lane 2.
  2. Will you embed it in something you sell, or host it for other people? If yes, drop the source-available tier or buy the commercial license, and re-read the open-core directories.
  3. Who owns what the agent produces? A framework gives you an agent loop and leaves the record to you. An assistant keeps its own memory. If a decision, an owner and an outcome have to outlive any one agent or model, you need a workspace layer on top of whichever agent you pick.

Where Maskin fits, honestly

Maskin is not an agent framework in the LangChain or CrewAI sense, and it is not a chat assistant. It is an open source workspace (Apache 2.0, checked in the repo) where agents work on typed objects: insights, bets, tasks and the relationships between them. Agents run in ephemeral sandboxed sessions, and the default agent is the Claude Code CLI, with Codex as an alternative. They read and write the workspace through Maskin's MCP server, the same API the web UI uses.

What that means for the lanes above:

  • It complements frameworks and assistants. The MCP server has an HTTP variant for agents that run outside Maskin's own containers, so an MCP-capable agent can in principle read and write the same objects. We have not published a tested recipe for connecting the projects above, so treat that as something to prototype, not a documented integration.
  • It is early. Maskin has single-digit GitHub stars at the time of writing, against tens or hundreds of thousands for most of this page. Evaluate the architecture, not a track record.
  • Local models are not a validated path today. If running a local model is a hard requirement, OpenClaw (local models are plugins) or Hermes Agent (any model endpoint) fit better.
  • Self-hosting requires Docker and Docker Compose on the host, per the repo README.

Choose Maskin when the pain is not "which agent" but "where does the work live, who owns it, and did it work". The closed-loop workspace explains the model, and the MCP tools reference lists what agents can do inside it. FAQ

What are open source AI agents?

Open source AI agents are agent software with public source code under a license that lets you run it yourself. That covers libraries such as LangChain, ready-made assistants such as OpenClaw and visual builders such as n8n. Licenses differ: n8n and Dify are source-available with commercial limits, while most of the field is plain MIT or Apache 2.0.

What are the best open source AI agents?

It depends on the job. For building your own agents, LangChain, CrewAI, the OpenAI Agents SDK and Microsoft Agent Framework are the large Python and .NET options, and Mastra covers TypeScript. For a ready-made assistant, OpenClaw, Hermes Agent and Letta. For visual workflows, n8n and Dify. For coding, see the separate coding-agents page.

Are open source AI agents free?

The software license is free for MIT and Apache 2.0 projects, but you still pay for hosting and for model calls unless you run a local model. Some projects also sell commercial products around the open code: CrewAI's AMP Suite, and n8n's Enterprise License for its .ee. files. Free to download is not the same as free to run.

Can you use open source AI agents commercially?

Under MIT or Apache 2.0, yes, including inside a product you sell. Under n8n's Sustainable Use License you can use it for your own internal business purposes but not resell or host it for others without an agreement. Dify requires written authorization for multi-tenant use and keeps its logo in the frontend. Check the LICENSE file, not the badge.

How do you build open source AI agents?

Pick a framework that matches your language: Python (LangChain, CrewAI, OpenAI Agents SDK, Google ADK, smolagents, Pydantic AI), .NET (Microsoft Agent Framework) or TypeScript (Mastra). Define the agent's instructions and tools, add MCP servers for external systems, and decide where its decisions and outputs are stored, because most frameworks leave the record to you.

Which open source AI agents can run locally?

OpenClaw's README says its state, memory and credentials live on your hardware, with local models as swappable plugins. Hermes Agent works with any model endpoint you point it at, and the OpenAI Agents SDK is provider-agnostic; check each framework's docs for local endpoints.

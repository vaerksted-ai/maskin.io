Self-hosted AI agents — the 2026 OSS landscape, honestly categorised

A self-hosted AI agent is an OSS agent framework you install on infrastructure you control — Docker, bare metal, or Kubernetes — so the model calls, the state, and the tool integrations all run on hardware you own. The OSS space is not flat. In 2026 it splits into four real categories: stateful-agent frameworks (Maskin, Letta, Cheshire Cat, Agent Zero, Paperclip), workflow-node builders (n8n, Flowise, Dify, EpicStaff), RAG chat frontends (Open WebUI, LibreChat, AnythingLLM, Bionic GPT), and coding-agent control planes (amux, Crewship, Preloop, Vornik and eight others). Which one you want depends entirely on the object of work — this page tells you which category your work sits in, and points you at the shortlist for that category.

Every canonical 2026 listicle answering this query — Kiebot’s Self-Hosted AI Agent Landscape: 16 Products (June 2026), Digest.Pro’s Top Platforms (August 2026), Lushbinary’s Best Self-Hosted AI Agents 2026 (April 2026) — mixes all four categories into a single flat list. Buyers typing “self-hosted AI agents” want the framework that fits their work. Mixing a Docker-node workflow builder with a stateful agent framework and a RAG chat UI does not answer that question. This page runs the split.

Key takeaways
  • The category is four categories. Stateful-agent frameworks, workflow-node builders, RAG chat frontends, and coding-agent control planes ship as separate shapes with separate object models. Any listicle that mixes them costs you an evaluation cycle.
  • License is a load-bearing filter. Apache 2.0 (permissive), AGPL-3 (network-copyleft), MIT (permissive), and source-available (commercial restrictions) each carry different obligations. Filter by license shape before you filter by features.
  • Docker is table-stakes. Every entrant on this page ships a Docker install. If a self-hosted-AI-agent project doesn’t, it isn’t ready for production self-hosting in 2026.
  • The stateful-agent category is where Maskin sits. Alongside Letta, Cheshire Cat AI, Agent Zero, and Paperclip — the frame is “persistent typed state + human approvals,” not “chat” and not “coding tasks.”
  • Reddit r/opensource owns the SERP head. For peer signal before installing anything, r/opensource’s self-hosted AI agents thread is the highest-signal community discussion currently on this query.

What “self-hosted AI agent” actually names in 2026

The phrase covers any OSS project where three things are true: the software is open source under a license that permits self-hosting, the code runs entirely on infrastructure you control (Docker host, Kubernetes cluster, laptop, on-prem server), and the model calls can be routed to a self-hosted LLM (Ollama, vLLM, TGI, LocalAI) if you want zero data egress. The privacy-conscious operator’s default read is that model calls should be routable to a local endpoint, even if in practice most self-hosted deployments still call a hosted API for the frontier models.

That is what the phrase doesn’t cover: SaaS AI agents with an “on-prem enterprise tier,” managed cloud offerings with a self-serve install, and AI agents behind a commercial cloud API. If the vendor’s business model is that you pay them monthly for their infrastructure, the product is not self-hosted regardless of whether they ship a Docker image.

Inside that definition, the shape of the product still varies wildly. That is where the four-category split earns its keep.

Category 1 — Stateful-agent frameworks

The stateful-agent category is where the agent holds persistent memory across turns and sessions, works on typed first-class objects (not chat messages), and hands off to humans at approval gates. The buyer is a small team or privacy-conscious operator whose work is a decision loop — signals in, bets shaped, tasks executed, outcomes validated — not a single Q&A turn.

Category 2 — Workflow-node builders

The workflow-node category is a visual editor where you drag nodes onto a canvas, wire inputs to outputs, and the result is a runnable agent flow. Every entrant here reads like a spiritual successor to Node-RED, adapted for LLM calls. The buyer is typically automating a known workflow (webhook in → LLM → tool call → response out), not exploring an open-ended decision loop.

Category 3 — RAG chat frontends

The RAG chat category is a self-hostable ChatGPT-shaped UI wired to your own model endpoints and (usually) a document ingestion pipeline. The buyer is looking to give a team ChatGPT without sending prompts to OpenAI, and to point the same UI at internal knowledge for retrieval-augmented answers.

All four fit a “give people ChatGPT that doesn’t leak” job; none are agent frameworks in the stateful-loop sense.

Category 4 — Coding-agent control planes

The coding-agent category is a dashboard that sits above a fleet of coding agents (Claude Code, Codex, OpenHands, Aider, Cline) and manages the queue, the sandbox, the approvals, and the audit log. The buyer is a developer or platform engineer running multiple parallel coding tasks and needing a control surface.

This is a full field in its own right — twelve OSS entrants shipped in 2026 alone (amux, Crewship, Preloop, Nora, Musematic, Mission Control, Clawix, Vornik, Zoink, herdctl, danrex/fleet, VNX). How to pick — three questions

The four categories look overlapping on a features grid. They stop overlapping the moment you ask the buying question in terms of the object of work.

  1. What is the object of work? A task in a wired workflow → workflow-node builder. A chat turn → RAG chat frontend. A coding task → coding-agent control plane. A decision that runs from signal to validated outcome → stateful-agent framework.
  2. Persistent state or ephemeral chat? If the agent needs to remember what it decided last week to inform what it decides today, you are in the stateful-agent category. If every turn stands alone or every workflow run starts fresh, one of the other three fits.
  3. What license terms hold for your commercial use? Apache 2.0 and MIT permit almost anything. AGPL-3 requires network-service source disclosure. Source-available and Sustainable Use licenses restrict reselling the software as a service. Filter by license shape before you filter on features — retrofitting license constraints after you have picked a tool is expensive.

If the answers point you at a stateful-agent framework, the sub-decision is what shape the persistent state takes, and that is where Maskin’s typed object graph vs Letta’s memory buffer vs Cheshire Cat’s plugin store vs Agent Zero’s tree becomes the real cut.

FAQ

What is a self-hosted AI agent?

An OSS agent framework you install on infrastructure you control, so the code, the state, and (optionally) the model endpoint all run on your hardware. Self-hosting differs from managed / cloud AI agents in that the vendor never sees your prompts, the data never leaves your network, and you own the operational surface — patching, backups, scaling, uptime.

Can you self-host AI agents in 2026?

Yes, and it has become substantially easier over the last twelve months. Every entrant on this page ships a Docker Compose or Kubernetes install that runs in under an hour on commodity hardware. Model calls can be routed to a hosted API (OpenAI, Anthropic) for frontier capability or to a self-hosted model server (Ollama, vLLM, TGI) for zero data egress.

What is the best self-hosted AI agent?

There is no single answer, and any listicle that gives you one is skipping the buying question. The best pick depends on the object of your work: a stateful-agent framework (Maskin, Letta) for decision loops; a workflow-node builder (n8n, Flowise) for wired automations; a RAG chat frontend (Open WebUI, AnythingLLM) for team ChatGPT; a coding-agent control plane (amux, Crewship, Preloop) for coding fleets.

Which self-hosted AI agents run on Docker?

All four categories are Docker-first. Every entrant listed on this page ships a Docker Compose install as the primary path. Kubernetes deployments are available for the enterprise-shaped entrants (Bionic GPT, EpicStaff, Musematic, Clawix). Bare-metal or pip installs are available for the lightest entrants (Letta, Flowise, n8n).

Are there free self-hosted AI agents?

Yes — every entrant on this page is free to self-host under its respective OSS license. Your only costs are the infrastructure you run the software on (VPS, home server, K8s cluster) and the model calls your agents make. If you self-host the model too (Ollama on GPU hardware, or CPU-only for smaller models), the ongoing spend can be near-zero at solo scale.

How should I read the license column?

License shapes on this page are the four-way categorisation a commercial buyer typically filters on. Permissive (Apache 2.0, MIT) is the safest resting place for a small team — modify freely, ship without obligation. Copyleft (AGPL-3, GPL-3) requires derivative works to stay open; network-copyleft in particular can bite if you fork the project and expose the modified fork over a network. Source-available means the source tree is readable but carries commercial-use restrictions — check the specific clauses before betting on it. Fair-code (n8n’s Sustainable Use License is the canonical example) is free for internal use but restricted for hosted redistribution. Filter by license shape first, then by features. Verify the exact SPDX identifier, version, and commercial-use terms on each project’s readme before relying on it for a regulated deployment — licenses drift, and this categorisation is a starting filter, not a legal opinion.

Is n8n a self-hosted AI agent?

n8n is a self-hosted workflow-node builder that has added AI-agent nodes over 2025-2026. If your work is a wired workflow with an LLM step, n8n fits. If your work is an agent that needs to hold state and reason across turns, n8n’s workflow model is a poor fit — you want a stateful-agent framework instead.

What about self-hosted AI voice agents?

Voice agents are a specialisation: they wire a self-hosted speech-to-text stack (Whisper, faster-whisper) and a text-to-speech stack (Piper, XTTS) around one of the agent frameworks on this page. Most stateful-agent and workflow-node entrants can be extended with voice pipelines; check the project’s community modules before betting on it as a first-class feature.

Where do I find self-hosted AI agents on GitHub?

Every entrant listed here has a public GitHub repo. The github.com/topics/self-hosted-ai topic tag surfaces the wider category. For peer signal before committing, the Reddit r/opensource thread self-hosted AI agents that run 100% locally is the highest-signal community discussion currently indexed.

Self-hosted vs hosted — how do I decide?

Hosted is faster to start, slower to control. Self-hosted is slower to start, and gives you full control over data residency, model routing, cost profile, and integration surface. If the workload touches regulated data (health, finance, legal) or the vendor’s pricing scales badly with your usage, self-hosting usually wins. If the workload is exploratory and cost sensitivity is low, hosted usually wins.

Start with the category, not the shortlist

The single most common failure mode when picking a self-hosted AI agent in 2026 is skipping the category question and jumping straight into a shortlist that mixes all four categories. That path leads to comparing a chatbot UI to an agent framework on features that only make sense within one category, and re-doing the evaluation once you realise the tool doesn’t fit the shape of your work.

Start with the object of work. That names the category. Then filter by license shape and install shape. Then pick from the two or three entrants that survive. Every category has three-to-five OSS entrants worth shortlisting; every shortlist is faster to evaluate than the twenty-vendor flat listicle the SERP will hand you.

Maskin sits in the stateful-agent category alongside Letta, Cheshire Cat, Agent Zero, and Paperclip. If that is the shape of your work — a decision loop with persistent typed state, MCP tool interop, and human approvals at judgment gates — Maskin is what the object model was built for.

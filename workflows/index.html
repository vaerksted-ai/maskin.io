Workflows you can run on Maskin

Each workflow closes the loop on an outcome — a page that ranks, a reply that lands, a citation that resolves — not on a task completed. Humans keep the gate on the decisions that need taste; agents run the mechanical middle. Pick the outcome you want and the workflow is the shape of what to run.

These three are the MVP set. More will land as the catalogue grows and other outcome shapes stabilise. If the outcome you need isn't here yet, tell us — we run the catalogue based on what real teams ask for.

SEO
The SEO publisher workflow
One shaped SEO bet in, one indexed, snippet-eligible article out. Research, draft, human approval, publish, track. The loop closes on a ranked page.

How to read a workflow page

Every workflow page is shaped the same way. The title is the outcome, in the language a product person uses — not the primitive that implements it. The lead paragraph is the plain-English shape of the arc: what goes in, what comes out, what the human owns. A video walkthrough sits below (the first three drop this week). Then the description — what it does, who it's for, and what closes the loop. Below the fold: the primitives it's composed from — loops, agents, MCPs, triggers — for anyone evaluating it as a system to run on their own instance.

The outcome-first framing is deliberate. Workflows are named for what they produce, not for the pieces that produce them. If you want the framework behind the primitives, the agent skills vs MCP vs cursor rules vs workflows piece maps the layers cleanly; the agentic workspace primer covers the object graph everything runs on.
